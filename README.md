# ERC-8004 registry snapshots — collection and QA code

MIT · tag `v2.0.0` · companion to the Zenodo deposit https://doi.org/10.5281/zenodo.22047444 (v2.0.0)

Python 3.10+ code that produced and audits two complete snapshots of the ERC-8004
Identity Registry on 13 EVM networks (`mc_t1` 2026-08-10, `mc_t2` 2026-08-16), plus the
follow-up certainty-stratum validation, two-phase estimator simulation, and 47-day
liveness/network pass (`mc_t3p`, 2026-10-02).
The data files themselves are **not** in this repository; they are the Zenodo
deposit (CC0). This repository is the Code Availability of the Data Descriptor
that documents the deposit and of the analysis paper built on these snapshots.

Scripts locate data relative to the repository root (`_chain/`, `_enrich/`). There
are no machine-local paths.

## Verify the deposited files (no RPC, no cache)

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
source .venv/bin/activate
pip install -r requirements.txt

python unpack_deposit.py --deposit /path/to/zenodo/download

MC_DIST=/path/to/zenodo/download python _enrich/scripts/mc_verify_deposit.py
python _enrich/scripts/mc_qa_audit.py --label mc_t1 --cards 0
python _enrich/scripts/mc_qa_audit.py --label mc_t2 --cards 0
python analysis_v2/certainty_score_deposit.py
```

To reproduce the two-phase estimator coverage grid, modified-Wilson check, label-error
sensitivity, and heavy-tailed finite-population simulations offline from the unpacked
`v2.0.0` deposit (requires `numpy` and `scipy`, included in `requirements.txt`):

```bash
python analysis_v2/p1_estimator/p1_coverage.py
python analysis_v2/p1_estimator/p1_tables.py
python analysis_v2/p1_estimator/p1_mwilson.py
python analysis_v2/p1_estimator/p1_label_error.py
python analysis_v2/p1_estimator/p1_weights_sim.py
```

To rebuild all Data Descriptor and analysis-paper figures offline from the unpacked
`v2.0.0` deposit (requires `matplotlib`):

```bash
python _enrich/scripts/make_figures.py
python analysis_v2/make_v2_figures.py
```

`mc_verify_deposit.py` reads the downloaded archives directly (`MC_DIST` points at the
folder holding them) and runs 75 checks that close inside the deposit: checksums, each
census against its own metadata, the panel against the census on every shared column,
flag `C` re-derived from `service_classes`, the tier histogram and strata against
`MC_SUMMARY`, every surrogate group checked for internal uniformity, the probe records
checked for keying, positive-integer `host_group` surrogates, and absence of URLs or raw
hostnames, the annotation layer rebuilt from its raw labels (κ recomputed,
`adjudication.md` and `consensus.csv` regenerated byte for byte), the certainty-stratum
coding layer verified against `mc_t2` probes and coder-1 controls, `p2_results.json`
checked for URL-free schema integrity, the mc_t1 re-probe layer (`probes_s11_repair.json`,
summarised by `MC_ENDPOINT_UNIT_repaired.json`) recomputed against the reconstruction it
corroborates, and the two snapshots compared for churn. Exit status is non-zero if
anything fails.

`mc_qa_audit.py` is the independent recomputation of the headline figures from the CSV and
JSON files, plus the codebook invariants: 163 checks per snapshot against a deposit, 164
against a working copy. `--cards 0` skips the card-hash-vs-cache layer, which needs the
fetch cache and the raw `tokenURI`; neither is deposited, and on an unpacked deposit the
layer says so and stops. Expected: both runs exit 0 with no discrepancies.

## What the deposit describes rather than reproduces

All registrant-supplied free text and network identifiers — `tokenURI` strings,
registration card bodies, 2 KB probe response snippets, full endpoint URLs, and endpoint
hostnames — are excluded from the deposit. In their place:

| Instead of | The deposit has |
|---|---|
| `tokenURI` | `uri_scheme`, `uri_media_type`, `uri_encoding`, `uri_bytes` |
| `tokenURI` identity | `uri_group` — 1-based integer shared by byte-identical values |
| `card_hash` | `card_group` — 1-based integer shared by normalized cards |
| probed URL | `endpoint_group` — 1-based integer shared by identical probed URLs |
| endpoint / card hostnames | `host_groups` (panels), `host_group` (probes, summaries, repair, coding) |
| free-text service names | `service_classes` collapsed to a closed vocabulary |

`_enrich/scripts/mc_deposit_shape.py` implements the structural derivations. Surrogate
group ids are assigned by order of first appearance, jointly over both snapshots: they are
not hashes, cannot be inverted, and cannot be used to test a candidate value against the
corpus. See `DATA_DICTIONARY.md` in the deposit for the full schema.

To check the derivation against data this project did not produce:

```bash
python _enrich/scripts/mc_stub_crosscheck.py
```

It re-derives the structural fields from the 10,000 Ethereum registrations that Liu
published with `tokenURI` verbatim under CC0 and compares them with what ships here. The
reference file is not redistributed: download `agents_core.csv` from `doi:10.7910/DVN/HJZW8Q`
and place it at `_raw/extracted/agents_core.csv`. Expected: agreement on all four fields for
9,999 of 10,000, the exception being a registration that changed its field between the two
collection dates.

| File | Role |
|---|---|
| `mc_census.py` | census of every token in the Identity Registry at a recorded per-chain block |
| `mc_fetch_score.py` | resolve registration cards, probe endpoints, write the scored panel |
| `mc_mint.py` | mint-event scan (`Transfer` from `0x0`) |
| `mc_reputation.py` | Reputation Registry feedback |
| `mc_ipfs_recover.py` | multi-gateway recovery of `ipfs://` cards |
| `rpc_pool.py`, `r_spec.py` | RPC pooling; pre-registered probeability filter |
| `mc_deposit_shape.py` | the derivations that describe registrant text: media type, vocabulary, error class |
| `build_package.py` | assembles the deposit from the working tree under a strict allowlist and applies those derivations |
| `mc_verify_deposit.py` | the 75 checks that close inside the deposit |
| `mc_stub_crosscheck.py` | the derivation checked against third-party verbatim data |
| `mc_qa_audit.py` | independent recomputation of headlines + invariants |
| `mc_qa_endpoint_unit.py` | S11mc (distinct live endpoints; rebuilds from raw `uri_cache` on the working copy; on a deposit `MC_ENDPOINT_UNIT.json` ships precomputed) |
| `mc_recover_probes.py` | reconstructs `mc_t1/probes.json` from the frozen panels via D/E constraints and verifies exact panel rescoring |
| `mc_s11_repair.py` | re-probes under-determined `mc_t1` endpoints; writes the `probes_s11_repair.json` / `MC_ENDPOINT_UNIT_repaired.json` audit layer |
| `mc_qa_reputation.py` | reputation-layer QA (runs offline on the unpacked deposit) |
| `mc_probe_method_audit.py` | GET vs. POST JSON-RPC / `agent-card.json` probe comparison (live network) |
| `mc_coding_sample.py`, `mc_coding_annotator_packages.py`, `mc_adjudicate.py` | stratified sample and annotation tooling (`mc_adjudicate.py` runs offline on the unpacked deposit) |
| `make_figures.py` | rebuilds the dataset pipeline and per-network figures offline from the unpacked summaries (needs `matplotlib`) |
| `analysis_v2/certainty_score_deposit.py` | recomputes the certainty-stratum PPV estimate directly from the unpacked `certainty_coding.zip` (deposit v2.0.0) |
| `analysis_v2/make_v2_figures.py` | rebuilds the four measurement-study figures (`fig1_estimator`, `fig2_per_network`, `fig3_concentration`, `fig4_hosting`) offline from an unpacked v2.0.0 deposit (needs `matplotlib`) |
| `analysis_v2/p1_estimator/*.py` | offline coverage across 108 designs (`p1_coverage.py`, `p1_tables.py`), modified-Wilson check (`p1_mwilson.py`), label-error bounds (`p1_label_error.py`), and heavy-weight simulation (`p1_weights_sim.py`); `p1_weights_extract.py` and `certainty_coding/{build_package,score,token_level}.py` document working-copy construction |
| `analysis_v2/p2_network/*.py` | 47-day endpoint re-probe (`reprobe.py`), sequential per-host circuit-breaker verification (`repair_breaker.py`), DNS/TLS/HEAD network pass (`netlayer.py`), and aggregate-only analysis (`p2_analysis.py` → `p2_results.json`; requires working copy + live network) |

`mc_adjudicate.py` rederives the disputed annotation items from the two raw label files and
rewrites `consensus.csv` and `adjudication.md`. It takes `--in` and `--out` and tolerates
either key column, so it runs both on a working copy (keyed by URL) and on an unpacked
deposit (keyed by `endpoint_group`); `mc_verify_deposit.py` invokes it to confirm the
regenerated files match byte for byte.

`build_package.py` reads the unpublished working tree and writes the sanitized
Zenodo `v2.0.0` deposit (`submission/Zenodo/dist_submission/`) under an explicit
allowlist; it is shipped so the deposit construction is auditable.

Re-running the **collection** (census / fetch / mint) requires public RPC access and
hours of wall time; it is not needed to verify the deposit.

Column definitions: `DATA_DICTIONARY.md` in the Zenodo deposit. Coding rubric:
`CODING_RUBRIC.md` inside `coding.zip`.
